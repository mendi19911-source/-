# מערכת ניהול מלאי — Phase 1

מערכת CRM פנימית לניהול קטלוג מוצרים ומלאי (מולטי-מותג / מולטי-מקור), לפי המפרט ב-Phase 1.
ממשק RTL מלא בעברית. שרת Node/Express + Prisma, לקוח React + TypeScript + Tailwind.

## מבנה הפרויקט

```
inventory-crm/
├── server/     Express + TypeScript + Prisma (SQLite ב-dev)
└── client/     React + TypeScript + Vite + Tailwind (RTL)
```

## הרצה מקומית

### שרת (server)

```bash
cd inventory-crm/server
cp .env.example .env
npm install
npx prisma migrate dev   # יוצר את מסד הנתונים ומריץ seed (כולל משתמש admin)
npm run dev               # http://localhost:4000
```

משתמש ברירת מחדל שנוצר ב-seed: `admin` / `admin123` (ניתן לשנות דרך משתני הסביבה
`SEED_ADMIN_USERNAME` / `SEED_ADMIN_PASSWORD` לפני ההרצה הראשונה, ומומלץ להחליף סיסמה
בפועל כשתתווסף מסך ניהול משתמשים).

### לקוח (client)

```bash
cd inventory-crm/client
npm install
npm run dev   # http://localhost:5173, מפנה קריאות /api לשרת בפורט 4000
```

התחברות דרך http://localhost:5173/login.

## מעבר ל-Postgres (production)

1. ב-`server/prisma/schema.prisma`: שנה `provider = "sqlite"` ל-`"postgresql"`.
2. עדכן `DATABASE_URL` בקובץ `.env` לחיבור Postgres.
3. שקול מעבר משדות `Float` לשדות `Decimal(10,2)` עבור מחירים, לדיוק מלא (SQLite לא תומך ב-Decimal).
4. הרץ מחדש `npx prisma migrate dev`.

## מה נבנה (Phase 1)

- **מותגים / קטגוריות (היררכיות) / ספקים** — ניהול חופשי, לא רשימה נעולה; ניתן להוסיף "תוך כדי תנועה" ממסך המוצר.
- **מוצרים + וריאציות (SKU)** — טבלה ראשית עם חיפוש/סינון/מיון, מסך פרטי מוצר עם טבלת וריאציות.
- **מחירים ורווחיות** — חישוב אוטומטי של עלות כולל מע"מ, מחיר מכירה לפני מע"מ, ואחוז רווח; דגל "רווח נמוך" מתחת ל-20%. עדכון מחירים בכמות (bulk update) לפי מותג/קטגוריה.
- **ניהול מלאי** — עדכון כמות עם סיבה, לוג מלא של כל תנועה (`stock_movements`), התראות מלאי נמוך.
- **ייבוא CSV** — מסך העלאה + מיפוי עמודות (למשל ייצוא מ-Shopify), עם תבנית לדוגמה להורדה. מוצרים/וריאציות עם שדות חסרים (מחיר עלות, ספק, מלאי) מסומנים כ"לא שלמים".
- **דשבורד** — מספר מוצרים/SKUs, שווי מלאי (עלות/מכירה), מלאי נמוך, מוצרים לא שלמים, פילוח לפי מותג/קטגוריה.
- **לוח משימות לעובדים** (`/tasks`) — לוח קנבן (לביצוע/בתהליך/הושלם) עם גרירה-ושחרור, עדיפות, תאריך יעד, שיוך לעובד/ת (טבלת `employees` נפרדת, עם הוספה מהירה מתוך הטופס), ופס סיכום דמוי-דשבורד בכניסה (סה"כ, באיחור, להיום, הושלמו היום).
- **אימות** — התחברות משתמש יחיד (session-based), טבלת `users` עם שדה `role` להרחבה עתידית.

תשתית ה-DB כוללת גם מקום שמור (בהערות בסכימה בלבד) לטבלאות Phase 2 — לקוחות עסקיים ותמחור מדורג — לפי סעיף 6 באפיון.

## פערים / החלטות עיצוב שכדאי לדעת עליהן

- אין עדיין מסך ניהול משתמשים (auth הוא single-user לפי המפרט) — הוספת משתמשים כרגע רק דרך ה-seed / ידנית ב-DB.
- אחסון תמונות הוא בקישורי URL בלבד (כפי שהמפרט מתיר לשלב ראשון) — אין עדיין upload לקבצים מקומיים.
- ה-margin % מחושב על בסיס מחירים ללא מע"מ (עלות לפני מע"מ מול מכירה לפני מע"מ) — כך שההשוואה נשארת "אפל לאפל" ולא כוללת את המע"מ שנגבה עבור רשות המסים.
- `react-router-dom` נעול על 6.30.4 (הגרסה האחרונה בענף 6.x); קיימת אזהרת אבטחה (open-redirect) שמתוקנת רק ב-7.x — שדרוג ל-v7 הוא שינוי breaking (data routers) ולא בוצע בסבב הזה.
